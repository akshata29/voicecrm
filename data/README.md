# data/ - synthetic demo data and configuration

Everything here is **synthetic / illustrative**. Nothing is any real firm's product list, policy or call data;
the names, people, accounts and phone numbers are invented (`.example` domains, 555 numbers).

| Path | What | Model (`backend/voicecrm/domain/`) |
|---|---|---|
| `catalogue/products.json` | 1,395 products in 326 fund families with share classes and look-alike names (generated by `tools/gen_catalogue.py`; the first 189 products are the curated "core" the scripted calls refer to) | `catalogue.Catalogue` |
| `taxonomy/topics.json` | 20 controlled topics with English + Spanish synonyms - the values behind the CRM dropdown | `taxonomy.Taxonomy` |
| `templates/*.yaml` | the two summary templates (professional buyer, retail advisor); every section maps to a CRM column | `templates.SummaryTemplate` |
| `policies/policies.yaml` | per-market transcript retention (US off, UK on/365 d, EU on/1825 d - **examples**), notes policy, processing policy (transcript source per channel, default template per business line) | `policy.PolicyBundle` |
| `pricing.yaml` | **illustrative** unit prices for the cost model | `metering.PricingTable` |
| `crm/seed.json` | users, accounts, contacts (incl. two "Alex Kim"s), opportunities for the CRM simulator | `crm.CrmSeed` |
| `crm/field_profile.yaml` | how a note maps onto Dataverse columns in the optional "custom" profile | `adapters/crm/field_profile.py` |
| `calls/*.json` | 18 scripted calls with gold labels: the demo inbox, the offline transcripts and the golden evaluation set | `fixtures.ScriptedCall` |
| `audio/` | optional real recordings for live Speech tests (git-ignored); the offline path uses synthetic placeholder audio | - |
| `phone/phone-call.json` | the short two-voice script `tools/capture_phone.py` speaks to place a real call to the phone line (for the phone screenshots) | - |

Load everything through `voicecrm.data_loader` so schema errors surface immediately.

## Scripted calls (`calls/`)

Coverage: Teams, Zoom, Genesys (inbound, caller known only by phone), mobile in-person; English, Spanish and code-switching;
US, UK and EU markets; professional-buyer and retail templates; share-class traps (Class C vs A, near-identical fund names,
ETF vs mutual fund), an ambiguous call (class never said), a no-action call, competitor objection, privacy calls (card number,
medical disclosure, spelled-out e-mail and password) and two **legacy-name** calls that only a reviewer can teach the system.

Each file carries gold labels: products (exact `product_id`, ambiguity and acceptable ids), topics, seller tasks with due dates,
strings that must not leak, rapport keywords that must be kept, and the CRM account the call must match.

### Authoring rules

- `product_id`: `SYN-000001` ... (never a real ticker or ISIN). Share class keys: `A`, `C`, `Advisor`, `R6`, `R`, `I`, `ETF`, `W`.
  Find ids with `python tools\catalogue_lookup.py "equity income" [class]`.
- `topic_id`: snake_case from the taxonomy. `fixture_id`: kebab-case. Participant ids: `seller`, `cust1`, `cust2`, `int1`.
- Gold tasks are **seller / colleague commitments only**; customer promises are distractors. Task `keywords` must all occur in one turn.
- Relative dates resolve against `ScriptedCall.started_at`: bare weekday / "by Friday" = the next such weekday strictly after the call
  date; "next Tuesday" = that weekday of the following Mon-Sun week; "tomorrow" = +1 day; "end of the week" = Friday; vague phrases
  ("next week", "soon") = no date.
- Every gold label must be checkable against the script. Validate with:

```bat
cd backend
..\.venv\Scripts\python.exe -m voicecrm.eval.data_checks [fixture_id ...]
```

(it also runs in the test suite, together with the catalogue and taxonomy integrity checks).
